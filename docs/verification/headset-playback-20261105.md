# 耳机播放控制修复（2026-11-05，本地）

后续用户授权后，测试开发版本 **1.5.0-test.20261105.182903** 已上传成功；体验版由用户自行切换。见[测试上传记录](headset-playback-test-release-20261105.md)，下文未上传表述属于本地实施阶段。

## 行为

微信听读文章、场景整篇音频使用全局背景播放器；耳机/系统面板播放请求先暂停原生音轨，等暂停确认后复核当前身份、内容版本和权限，再从断点续播。点读使用原独立音轨，整篇续播时停止点读。

锁屏、切换其他应用保留整篇；成功导航离开学习页及卸载停止并清理。导航失败保留原会话，场景原图覆盖层及返回保留原规则。隐藏时取消尚未完成的页面播放动作并停止点读与正文测量；回前台同一有效版本复用播放器、读取原生时钟和暂停状态，恢复正文高亮及进度保存。

微信预加载只准备受控网络地址，不给原生播放器提前赋值 src，不下载不能直接交给背景播放器的本地整篇文件。H5 和单词音频保留原缓存方式。系统停止与播放错误后可重新加载受控地址；五档倍速沿用原设置及失败回退。

## 实现边界

- 原生全局监听按播放器实例只注册一次，向唯一活动所有者派发；销毁旧音轨不会停止新所有者
- 导航拦截捕获导航发起时的会话，仅在成功时停止该会话，不受应用/页面隐藏回调先后影响
- 听读权限核对使用独立代次，同时校验音轨、账号、文章身份；隐藏不会丢弃仍属于同一后台会话的失效结果
- 场景页面点击和系统续播分别校验，隐藏及会话释放使未完成的点击失效
- 系统暂停/停止会取消等待地址的播放代次，迟到地址不能再次调用原生 play
- 首次绑定背景音源前设置起始秒数；暂停后续播、结束后页面重播、切速及拖动沿用现有控制器

## 真机验收待完成

本轮没有连接可操作的 iPhone/蓝牙耳机，自动化媒体边界和构建结果不等于真实耳机验收。后续在设备上分别播放场景、听读：

1. 页面内、锁屏、切后台连续使用耳机暂停/续播，确认断点及五档倍速
2. 回前台确认按钮、实际进度和正文高亮一致，整篇与单词不重叠
3. 返回列表、切换页面后停止；导航失败和原图覆盖层不误停
4. 系统停止、播放结束后页面重播、音源过期重试及权限失效均正常

背景音频能力随小程序包声明，正式版本需通过微信平台对应审核。本轮未提交、推送、上传微信包、同步 OSS、部署 API/后台、操作数据库或修改生产版本记录。
