# CHG-0040 需求与设计复核（2026-11-10）

> 本文保留修复前审计快照；最新实现与验证进展见[本轮修复记录](chg-0040-remediation-20261110.md)。下文缺陷及“当前”描述对应审计时点。

结论：当前实现没有完整达到原始需求和 Figma 的交付标准。已有协议/许可数据能力、部分界面、游客与学习边界及隔离回归；实际测试环境仍走 legacy，新版主流程不可达；另有两处已复现的微信编译缺陷。不能将既有自动化通过、部署成功或旧兼容登录可用等同于本单验收通过。

本轮为只读复核：未改产品代码、配置、测试服数据、友盟开关或热更新进程。报告基于本地 test 当前工作区（含上一轮尚未推送的隐私同步修复），开发工具项目 dist/dev/mp-weixin 实际连接测试 API。上一轮已上传的微信开发版本不包含尚未推送的本地修复。

## 已确认的问题

### A01 / P1：首次告知与三选择流程在实际环境没有交付

原文要求未确认协议的用户进入首页显示首次告知，账号操作给出同意并开启、仅登录、先体验三种选择。当前 `privacy-service.ts:28` 的 published 判断要求完整正式正文；`shouldNotify` 又要求 published；`app-login-prompt.vue:97` 也用 published 决定是否显示新弹窗。测试环境正文为空，因此实际不会呈现 M01，账号操作仍走旧两按钮提示/原登录页，而非 M02/M07。

现有 API 实施计划明确采用了“只交基础能力、正式材料缺失沿用 legacy、夹具验证新流程”的阶段范围；这是阶段交付边界，与原 Word 的完整程序验收不同，不能据此将 T396、T401 等标为实际完成。正式材料缺失是需要补齐的输入，不能伪造正文、记录不存在的协议版本或直接强开统计来掩盖缺口。

代码：`src/services/privacy-service.ts:28`、`:47`；`src/services/consent-coordinator.ts:39`；`src/components/app-login-prompt/app-login-prompt.vue:97`。

### A02 / P1：新版登录按钮在微信编译产物中仍会失败

`app-login-prompt.vue:47—48` 仍动态导入 session/useAccountStore。当前微信产物将其转成 `await "../../services/api.js"` 与 `await "../../stores/account-store.js"`，解构结果为空。私有探针用 published 隔离状态执行真实组件的“仅同意协议并登录”事件，实际得到 **useAccountStore is not a function**，微信登录或业务 HTTP 尚未发起。主按钮共用此处理函数，也受影响。

上一轮修复了 privacy.ts/consent-coordinator.ts，但遗漏此组件，故“隐私请求恢复”不能代表“新版登录整体修复”。此缺陷即使补上正式协议配置也会存在。

代码：`src/components/app-login-prompt/app-login-prompt.vue:47`；产物 `dist/dev/mp-weixin/components/app-login-prompt/app-login-prompt.js:44`。

### A03 / P1：已有会话的首页跳过协议判断

`pages/home/index.vue:72—73` 也保留动态导入，在微信编译后成为路径字符串。恢复出账号后读取 `.privacy.published()` 抛异常，被该链末尾 catch 静默吞掉，后续 considerHomeConsent 不执行。

真实编译首页的隔离执行结果：游客时协议评估调用 1 次；恢复出账号时调用 0 次。这会漏掉已有账号的新版协议核对/更新告知，影响 T399/T400，不能只验证游客首屏。

代码：`src/pages/home/index.vue:72`；产物 `dist/dev/mp-weixin/pages/home/index.js:59`。

### A04 / P1：正式协议及第三方披露缺失，当前无法完整阅读与验收

测试环境三个正文端点均 404；实际协议页只显示未配置提示。友盟入口当前为复制官方链接、再到浏览器阅读，未在小程序提供完整第三方说明。T414 正式协议/披露无需登录可读的完整交付尚未满足。

配置不全时关闭真实分析，符合原文要求；缺少的是正式材料及生效验证，不能把空协议页算作协议阅读完成。

代码：`src/sub-packages/account/policy.vue:34`、`:37`；API `src/juya_api/privacy_service.py:14`、`privacy_api.py:143`。

### A05 / P1：独立许可与真实统计没有连成运行链路

前端 resolveAnalyticsConfig 恒返回 enabled=false；实际 analytics 为关闭实现或空身份/关闭上下文。API create_app 固定 analytics_receiver=None；preference_view 的 collecting 恒 false。即使补齐文档、登录并保存 enabled=true，当前实际构建也不会运行真实友盟统计，M06 的完整运行状态和 T401/T409—T413 正向链路尚不能验收。

目前的关闭策略正确保障了未具备条件时不采集；但五事件工厂、许可鉴权和去重的夹具测试不是 SDK 接通、自动行为核查、拒绝/撤回抓包的完成证明。后续需核实项目内 umtrack-wx 2.8.0 的实际自动行为，完成正式披露及控制适配后再接通，不能简单改 enabled 常量。

代码：`src/services/analytics-config.ts:12`、`src/services/analytics.ts:6`；API `src/juya_api/mini.py:51`、`privacy_service.py:160`。

### A06 / P2：隐私页政策链接实际对齐与设计不一致

M03/M08 中“查看友盟隐私政策”位于内容左侧 x=46。当前微信实际画面中它居中。组件虽然写 text-align:left，但没有覆盖按钮 flex 居中布局；全局 `.app-page button` 设置 display:flex/justify-content:center。应按微信实际生效样式修复，而非只检查 SCSS 字面值。

代码：`src/components/app-privacy-sheet/app-privacy-sheet.vue:234`、`src/styles/main.scss:39`；Figma M08 396:5956、396:5964。

### A07 / P2：按需登录状态的文案与高度没有按稿逐态还原

M02/M04/M05/M07 使用“登录后可收藏这篇听读”，底部“登录成功后，请再次点击收藏”；组件统一显示“登录后保存到你的账号”“请再次进行原操作”，没有收藏听读的上下文文案。首次与触发态使用同一个固定滚动高度 1180rpx，390 宽时连内边距约 658px；设计 M01 约657px，M02/M04/M07 约602px，不能用同一固定高度完成这些状态的还原。

文案差异为源码可确认；高度差异为按当前 CSS 与设计尺寸推导，正式配置路径未激活，仍需修正后逐态微信截图复核。隐私弹窗整体奶油白/墨绿/浅绿、约342宽、圆角、开关形状、原登录水彩方向基本沿用；不应宣称八态已像素验收。

代码：`src/components/app-consent-dialog/app-consent-dialog.vue:18`、`:52`、`:79`。

## 既有完成项与证明边界

上轮最近一次全量 pnpm check 与 134 文件/803 项测试通过；这是工程回归证据。测试没有覆盖当前真实编译的 app-login-prompt published 登录事件及已有会话首页协议评估，本轮私有探针已经复现两处缺陷，所以不能继续用“803 通过”证明本单无漏项。

API 的协议/许可模型、0027 扩展迁移、可信会话/独立统计偏好、事件鉴权/去重基础能力已有；必要学习业务与统计分离、未自动收集资料、未完成条件前不采集的方向符合。真实服务迁移/发布健康记录属于部署证据，不能取代产品验收。

## 建议补齐顺序

1. 修复并增加真实微信产物回归：登录组件与已有会话首页的动态导入缺陷。
2. 补齐实际版本化协议与第三方披露输入；测试环境用明确区分的隔离验收配置覆盖全部设计态，正式材料不由原型占位文案替代。
3. 逐态打通首次告知、两种主动登录、失败重试、已确认变体、统计许可开关及来源恢复，按 M01—M08 在微信开发工具逐态对照。
4. 单独完成真实统计控制适配、SDK 自动行为检查及正/反向抓包，再启用实际测试统计；保留材料不全/拒绝/退出/失效时的关闭条件。
5. 完成 iOS/Android 真机验收后，再将 T396—T415 标为实际通过。当前不能宣布本单已完整符合需求和设计稿。
