# 修订15批3：本人反馈与同条持续沟通

依据：2026-10-22已确认开发方案3.3；需求33章；T169—T178

## 实现

- 新增普通反馈子包U10列表、U11首次提交、U12详情与持续补充。U07本人反馈行、U03当前场景入口、U01账号聚合红点接入同一反馈服务，两底部导航保留学习与收藏
- 列表独立加载、分页及失败重试，失败保留可信内容；列表与账号入口只读取未读，不清除回复。详情时间线按服务端事件顺序展示用户说明、管理员回复、明确状态动作、截图和服务器时间
- 首次及每次补充均校验trim后1—500个Unicode字符、0—3张截图。各截图独立上传、重试或移除，保留成功ID，未知上传先查原回执；过期成功图只续签预览授权，不重新上传
- 提交复用持久幂等元数据。未知结果先只读查询原操作，明确重试冻结正文和原键；并发会话失效或账号变化时保留原操作键，重登后可查已接受结果，避免改换新键重复创建；失败不清输入、不自行宣告成功。成功后清理编辑器事务状态，允许连续创建或任意状态下反复补充；补充成功重取当前服务端状态和完整时间线
- 同账号会话过期锁定并遮蔽内存草稿，重新登录先查询结果，不自动重发；其他账号与明确退出清理草稿。私有说明和截图路径不写入持久存储。离开未提交输入使用现有原生返回保护，明确继续或放弃；未知提交离开则保留同账号内存恢复快照，文案明确离开不等于取消服务器提交
- U11来源引用经校验后用于登录恢复，携带稳定卡片和版本、不携带私人说明。首次提交成功以redirect替换表单，返回栈保留原U03或U10实例。反馈往返不修改原U03译文及可信阅读位置
- 来源有效时可打开当前发布详情，失效时仅显示安全中文/英文标题和不可用原因；不显示旧全文或恢复旧音频。历史缺英文时隐藏该行
- U12成功渲染快照后仅确认实际事件最大ID，最小ack不清新红点，随后重查未读聚合；同水位读标记结果未知时先查询原操作，查实成功不重复PUT，查无回执才原键重试，其他查询错误保留独立已读失败提示；读取或已读同步失败分别呈现并可重试，其他反馈和更晚事件仍保留未读

## 边界

- 联调使用隔离的合成内容安全适配器，未配置真实平台内容安全时保留输入并明确失败；不代表真实文字/图片审核服务验收
- 私有截图授权、真实图片解码与安全处理由API负责；微信原生选择/预览、系统返回保护和不同设备下显示需真机独立验收
- 草稿只保留当前进程内本人内存；进程重建或换号再回后，仍保留本人待确认操作元数据；先查结果，只有明确查无回执才开放重新填写。`rebind`严格沿用已查询的账号、键、路径和方法；冲突先恢复旧receipt，重填校验失败也不丢原键。私人说明不持久保存，不自动重发
- 本批不新增原生分享、额外底部导航、消息中心、实时客服或补充轮次限制
