# 修订15批2：正文查词

依据：2026-10-22已确认《开发方案-整合03修订15-待确认.md》3.2；需求7.7、9.2；T160—T168

## 实现

- 对话英文按统一API的ASCII词边界拆分，普通词与重点词均可点击；保留原高亮范围、译文状态和阅读位置。缩写、直/弯撇号缩写词、连字符及emoji之前的UTF-16偏移使用原文精确索引，标点与数字/下划线相邻片段不发起查询
- 请求只提交当前卡片、版本、行ID、原词和原始起止位置，采用正式生成的接口类型。主标题始终显示点击的原词，关联词形单独呈现，不将词形的IPA或音频作为原词结果
- 居中弹窗包含加载、本篇释义、通用词典、关联词形、无音标、查无结果和失败重试；内容高度封顶且内部滚动，关闭入口置顶。遮罩与关闭按钮均可退出，没有逐词收藏入口
- 查询按最新请求代次及账号/卡片/版本隔离，切词和关闭后旧结果不能覆盖当前弹窗。当前卡片失效立即关闭弹窗并结束受限音频操作；词典服务不可用显示实际错误，其他场景操作继续可用
- 点击词只查询，不预加载或播放发音，也不改变整篇音频状态。点击喇叭后沿用现有双音轨控制器，暂停整篇并保留位置和倍速；服务端决定实际读音，前端只提交原文引用。切词或关闭停止弹窗词音频，整篇须手动继续
- 发音沿用现有持久幂等、任务轮询及受控音频文件流程，没有新增第三播放器。发音失败可重试，页面隐藏、账号变化、版本变化和卡片失效清理相关任务与播放

## 验证

- TDD红到绿覆盖普通词/UTF-16拆分、实际对话点击、加载/失败/词形弹窗、迟到响应隔离、以及单词停止时整篇位置与倍速不变。补充真实详情组件回归验证点词不暂停、点击喇叭才暂停、关闭不续播、译文保留、卡片失效停止与销毁音轨
- 服务层回归验证点击喇叭之前没有发音请求，创建/轮询携带相同原文引用，且请求没有任意TTS文本或关联词形。Unicode回归确认 `İ ı ſ K` 为不可点击文本；API同步以 `re.ASCII` 修正了Python忽略大小写与JavaScript规则的差异
- 最终完整测试：45个文件、186项通过。`pnpm check`中的格式、代码、样式及类型检查全部通过。H5与微信小程序构建通过，微信产物验证9个页面配置及两个底部导航
- Figma设计上下文与截图：本篇释义 `283:14119`、通用词典 `284:3679`、关联词形 `284:4086`、查无结果 `284:4495`、加载失败 `284:4900`；新增图标来源见 `docs/design/asset-provenance.md`
- 集成执行者使用独立合成账号完成H5/API核验：`went`关联`go`且不借用其IPA、`don't`通用释义、重复`mobile`的第二处上下文、查无结果；整篇播放中点词保持播放，喇叭使整篇停在0:19，关闭后译文和位置保留，手动可续播

## 边界

- 浏览器词典测试使用明确隔离的合成词典fixture，不代表生产通用词典覆盖率。未配置真实词典时，接口明确失败，前端不使用假释义
- 当前验证环境没有真实TTS凭证，任务明确失败并验证了失败反馈；真实服务的读音质量、原词异读、微信真机音频与内部滚动需使用授权环境另行验收
- 本批不增加反馈、原生分享或其他后续批次界面；批1的来源队列与可信阅读位置逻辑保持既有回归覆盖
