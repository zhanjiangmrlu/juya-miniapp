# 修订15批4：原生分享与安全进入

依据：已确认方案3.4、需求基线34章及T179—T185。本批只实现分享与进入边界，加载、图片通用状态及隐私文案的批5工作保持独立

## 实现

- U01和有效U03接入微信好友/群与朋友圈回调。好友仅返回`title/path/imageUrl`，朋友圈仅返回`title/query/imageUrl`；没有描述、假成功提示或不受支持的取消回调。学习页使用固定品牌标题，场景使用当前公开发布的中文名与可用英文标题，历史缺英文时不拼接空行
- 分享参数只含`target=learning`或`target=scene&id=稳定编号`。接收及登录返回均使用白名单，移除队列、版本、发送者、Token与个人资料。分享单卡不接收来源快照，完成后留在详情并提供“前往学习页”；下线目标显示安全U05及“返回学习页”，既有收藏/记录来源保留“返回列表”
- 公开请求使用独立匿名GET/HEAD边界，只允许公开摘要与派生封面路径，丢弃传入身份及幂等请求头。DTO使用正式生成的`PublicSceneShare`。公开摘要失败或封面字段/比例异常时不开放菜单与原生按钮，也不使用私有原图回退
- 原生完整模式先下载两张公开封面并核对真实600×480、600×600像素，均准备成功才允许分享。H5只提供预览和真实微信菜单说明。摘要模式不准备私有正文或音源，只展示公开标题、公开派生图或品牌资源
- App启动/重新显示、官方类别变更监听、页面入口、Session、平台HTTP/上传及音频/原图准备均检查官方运行类别。`browseOnly`不由查询开关或场景号1154猜测；已有业务会话也不能调用恢复资料、统计、登录、词典、音频或学习写入
- 已显示的私有页面在模式收紧时隐藏正文与个人区域。U03同步销毁播放器、取消音源准备、撤销旧图片/正文回写并清空当前卡；独立原图覆盖页同时清除自身图片与注册上下文、废弃在途结果，改为匿名摘要。恢复完整模式重新确认本人身份、读取当前发布；覆盖页只恢复安全单卡目标，不恢复原队列或旧私有文件
- 私页和未就绪页面隐藏两个分享菜单，仅U01/有效U03按就绪状态开放。隐藏页面的组件不再改变当前页面菜单。意外触发未就绪回调时仍明确指定品牌图和学习目标，防止省略字段后采用个人页面截图
- 无业务会话时进入默认未勾选的主动登录。失败保留安全目标并可主动重试；成功后重新读取目标，目标下线或换版不恢复旧正文。仅浏览页面只说明微信真实完整入口，不声称脚本已经打开完整模式

## 模式切换与未知结果

- 发送前的`browse_only`表示本次没有发出。全新操作可清理未发出的键；已有待确认原事务不能因为这次重试未发出而清键。默认recover在查无回执之后被模式阻止重试时也保留旧键
- 已发请求的响应跨越模式变化时使用`session_changed`未知语义，即使已经切回完整模式也不接受迟到结果。本人元数据保留原键，完整模式后先查询原receipt，不能换键重复提交。真实组合回归确认原POST只发出一次
- U01模式收紧时同时使旧列表请求失效并释放busy。真实页面回归覆盖旧请求未结束就进入/退出摘要：完整模式可以重新请求当前列表，旧列表迟到不覆盖新结果
- 已经发出的网络请求不能撤回服务器提交。停止播放器/取消准备与拒绝迟到响应，不等于撤销学习、反馈或其他服务端操作

## 原生能力边界

- 微信好友图片显示比例5:4、朋友圈1:1；朋友圈回调只接受同步内容，没有本实现可依赖的取消结果或发送成功回调，依据[微信官方Page类型](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.page.d.ts)。运行模式依据官方`getApiCategory`及`onApiCategoryChange`，参见[官方API类型](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)
- 摘要准备与实际微信发送之间仍可能发生发布变化。接收方始终按稳定编号重查当前发布；已准备的公开封面不是全文、身份或私有媒体访问凭证。未就绪/失败入口被关闭，异常回调明确返回安全品牌目标
- 真正的好友/群发送、朋友圈客户端入口、取消行为、封面本地文件兼容、官方browseOnly及完整入口切换仍需实际AppID与iOS/Android真机验收。自动化端口注入和H5预览不冒充原生验收；H5仅改hash时uni页面实例可能复用，分享冷启动验证使用重新加载
