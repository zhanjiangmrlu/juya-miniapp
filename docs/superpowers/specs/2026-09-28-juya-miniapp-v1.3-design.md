# 句芽英语 V1.3 用户端设计说明

## 1. 目标与范围

在现有 `juya-miniapp` Vue 3 + TypeScript + uni-app 工程中完整交付句芽英语 V1.3 微信小程序用户端。实现 43 个正式页面标识、4 个兼容入口、手机和平板响应式布局，并接入 `juya-miniapp-api` 文档定义的用户端接口。

本次包含首页、学习列表、场景学习、当前页词汇和语块弹层、音频、逐句跟读、收藏、翻卡、学习历史、档案、联系方式、权益、消息、反馈、数据清空与账号注销。明确不实现后台端、支付、订单、价格、广告、发音评分、社交、长期录音或用户自建内容。

## 2. 实施策略

采用“共享底座 + 业务纵向切片”，而不是先制作全部静态页面或先一次性设计全部抽象。

1. 建立设计令牌、应用壳、请求与认证、错误映射、路由兼容及通用组件。
2. 完成 M01-M18 学习主链路，包括目录、场景、音频、弹层、跟读、完成和位置恢复。
3. 完成 M19-M25 收藏、条目详情、翻卡和学习历史。
4. 完成 M27-M37 档案、联系方式和权益。
5. 完成 M38-M47 消息、反馈、数据清空与注销撤回。
6. 完成平板重排、无障碍、视觉对照和全量回归。

每个切片同时交付页面、状态、接口、错误态、测试和中文 Git 提交，避免 UI 与逻辑长期脱节。

## 3. 分层与公共能力抽取

页面只负责编排用例、绑定页面级状态和渲染，不直接实现可复用状态机、网络策略或重复视觉结构。

### 3.1 基础展示组件

放入 `src/components`，不依赖具体业务 Store：

- `AppPage`：一级页、二级页背景与安全区。
- `PageHeader`：标题、返回与可选右侧操作。
- `SurfaceCard`：统一卡片边框、圆角和内边距。
- `AppButton`、`IconButton`：主次按钮、加载和禁用状态。
- `BottomActionBar`：固定底部操作与安全区。
- `AppTabBar`：首页、学习、收藏、我的四个固定入口。
- `EmptyState`、`ErrorState`、`LoadingSkeleton`：跨页面状态反馈。

### 3.2 跨页面业务组件

放入对应 `features/*/components`：

- `SceneCard`、`SceneListSection`：首页、学习、权益和历史共用。
- `AudioButton`：场景、词卡、收藏和跟读共用统一状态。
- `VocabularySheet`：词汇和语块共用底部弹层。
- `DialogueList`、`DialogueSentence`：场景与跟读共享内容结构。
- `EntitlementCard`、`FeedbackCard`、`LearningResultCards`：同一领域多页面复用。

### 3.3 公共逻辑

复用逻辑优先放入纯函数、组合式函数、领域 Store 或 Service：

- `shared/utils`：北京时间、文本规范化、脱敏、校时和格式化。
- `shared/navigation`：正式路由、Tab 路由、M04/M10/M11/M26 兼容映射。
- `services/http`：令牌、请求 ID、幂等键、超时、重试、刷新和错误映射。
- `features/audio`：唯一播放器实例和音频状态机。
- `features/recording`：麦克风权限、临时录音生命周期和清理。
- `features/learning-progress`：节流保存、离线队列、合并和幂等重试。
- `features/vocabulary-sheet`：弹层打开、返回滚动位置、收藏同步。
- `features/contact-profile` 与 `features/feedback`：敏感字段隔离和校验。

抽取以职责和真实复用为依据，不建立只包装一行调用的空壳组件，也不把所有业务塞入单个全局 Store。单个 `.vue` 文件接近 400 行时优先拆分业务组件或组合式函数。

## 4. 路由与页面组织

页面按业务目录组织：`home`、`learning`、`scene`、`favorites`、`profile`、`entitlement`、`feedback`、`account`。

- M01S、M05S、M09S、M09T 是所属正式页面的状态，不注册新路由。
- M04 重定向到 M01 并触发网络异常状态。
- M10、M11 返回所属 M09、恢复稳定来源位置并打开对应底部弹层。
- M26 使用 `reLaunch` 或 `redirectTo` 进入 M27。
- 底部 Tab 固定为首页、学习、收藏、我的；我的直接进入 M27。

兼容规则集中管理，页面和业务组件不得自行拼接旧路径。

## 5. 数据流与接口

### 5.1 启动链路

1. 渲染不依赖登录的品牌和首页骨架。
2. 恢复安全存储中的刷新令牌；没有令牌则调用 `uni.login`。
3. 调用 `POST /api/v1/session/wechat` 建立或恢复身份。
4. 成功后并行读取本人摘要、首页和未读数。
5. 失败时保留 M01，并打开 M01S；重新连接会重新执行微信登录。

### 5.2 请求层

请求层统一附加 Bearer Token、`X-Request-ID`、客户端版本和写请求幂等键。默认超时 10 秒；GET 网络错误最多重试一次；POST 仅在已有幂等键且调用方明确允许时重试。401 只触发一次令牌刷新，刷新失败后清理令牌并重新静默登录。

错误响应映射为领域错误和用户文案。页面不展示服务端堆栈、SQL、内部规则或原始异常对象。

### 5.3 契约化开发数据

接口 DTO 按 API 文档集中定义。开发环境的 mock adapter 与真实 transport 实现同一接口，通过环境配置切换。页面、Store 和领域用例不直接导入 mock 数据；生产构建不依赖演示数据。

## 6. 状态管理

- `sessionStore`：令牌刷新、登录状态和本人最小摘要。
- `homeStore`：首页、今日任务、连续学习和未读数。
- `learningStore`：模块入口、服务端已排序目录和当前场景摘要。
- `audioStore`：唯一音频目标和播放器状态。
- `sceneStore`：当前场景、中文开关、弹层和阅读恢复。
- `favoriteStore`：双标签筛选、滚动位置和翻卡游标。
- `feedbackDraftStore`：300 字文本和单张临时截图引用。
- `systemStore`：网络、审核能力开关和客户端校时。

权益状态、联系方式修改次数、反馈状态等服务端事实不进行乐观推导。命令成功后重新读取服务端投影。

## 7. 学习、音频与进度

场景打开前调用服务端 open 接口。完整内容、只读摘要和拒绝结果使用不同模型，禁止把只读预览转换为完整场景。稳定定位统一使用 `scene_id`、`sentence_id`、`entry_id` 和 `source_locator`。

音频全局只创建一个 `InnerAudioContext`。目标键为 `{target_type}:{target_id}:{version_id}`；新目标播放前停止并解绑旧目标，同目标再次点击执行暂停或继续。短期地址过期只刷新当前目标一次，失败不阻断正文。

滚动停止 800ms 后保存最后可见稳定位置。离线队列按场景合并阅读位置，保留最新位置；完成场景和完成翻卡命令不合并，并始终复用原幂等键。服务端确认前只显示“待同步”，不提前增加连续天数。

跟读录音只保存在本地临时目录。切换句子、重录、页面卸载、完成学习、后台超时或退出账号时停止音频并清理对应临时文件。

## 8. 视觉与响应式

用户端 PNG 是页面视觉权威。一级入口页使用柔光暖米白，二级页使用 `#F8F1E2`，模块色为 `#E3EFE6`，卡片色为 `#F8FAF5`，边框为 `#C9DED1`，主色为 `#2F7D61`。

样式使用 scoped SCSS，并在页面根节点下嵌套。颜色、间距、字号、圆角、阴影、层级和安全区放入 `styles/tokens.scss` 与 mixins，页面不得重复硬编码品牌令牌。

手机以 390x844 为主基准并回归 375x812；平板以 768x1024 为基准，通过容器宽度和 CSS Grid 重排同一套组件，不维护第二套业务实现。主按钮视觉高度不低于 44px，固定底部操作区使用安全区变量，正文、状态和错误不截断，图标有可访问文字，状态不只依赖颜色。

接口主题图优先于本地资源。开发态仅使用设计包中的可替换素材，不把页面截图裁切成生产 UI。

## 9. 异常与隐私

- 静默登录失败：保留首页并显示 M01S，不创建游客数据。
- 图片失败：显示占位与重试，不阻断正文。
- 音频失败：保留阅读能力，控件进入 FAILED。
- 权益校验失败：仅显示可信摘要，正文入口重新校验。
- 麦克风拒绝：仅禁用录音，其他学习功能继续可用。
- 反馈截图失败：保留文字草稿，可移除图片后提交。
- 内容安全拦截：显示 M43 合规文案，不回显内部规则。

微信号只在联系资料领域的必要状态中存在，不进入通用 Store、日志、埋点或页面快照。退出登录、清空学习数据或注销生效时清理本地进度队列、反馈草稿、录音和缓存正文。

## 10. 测试与验收

所有新增行为采用测试先行，先观察测试因缺少行为而失败，再实现最小代码并运行通过。

重点单元测试覆盖：

- M04/M10/M11/M26 路由兼容。
- 请求头、GET 重试、401 单次刷新和幂等键复用。
- 音频状态机、防叠播和地址过期重取。
- 录音权限、切换句子和临时文件清理。
- 北京时间问候、绝对到期时间和客户端校时。
- 进度队列合并、不可合并命令、重试和清空。
- 联系资料与反馈敏感字段脱敏。
- M01、M05、M09、M14、M19/M20、M35/M36、M42 的关键状态。

阶段提交前运行相关测试；完整交付前执行：

```text
pnpm check
pnpm test
pnpm build:mp-weixin
git diff --check
```

视觉验收在 375x812、390x844、768x1024 三个视口与对应设计稿对照。集中修正一轮，再做一次确认截图。

## 11. Git 提交策略

所有工作直接在 `main` 分支进行，不创建 worktree，不强推。提交类型使用英文 Conventional Commits 前缀，冒号后的说明使用中文，并按可独立验证的业务切片提交：

1. `docs: 确认 V1.3 用户端技术设计`
2. `feat: 建立应用底座与公共组件`
3. `feat: 完成学习主链路与统一音频状态`
4. `feat: 完成收藏复习与学习历史`
5. `feat: 完成学习档案与权益页面`
6. `feat: 完成消息反馈与账号生命周期`
7. `refactor: 完成平板适配与全量验收`

实际提交可按测试边界进一步拆分，但每个提交必须保持构建和对应测试可验证。
